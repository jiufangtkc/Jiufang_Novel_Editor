# 九方小說編輯器 (Jiufang Novel Editor) v0.1.6-Beta

這是九方小說編輯器的 v0.1.6-Beta 測試預發布版。
在長篇小說創作過程中，隨時記錄靈感、維護人物設定卡片是作家的日常操作。如果卡片需要額外手動點擊按鈕才能儲存，或者切換節點時未存檔導致心血遺失，會打斷原有的創作心流；同時，統計數據在重啟後若出現進度不一致，也會對寫作節奏造成干擾。

本次更新重點聚焦於「資料集卡片即時自動儲存」、「修復卡片編輯工具列前綴切換崩潰問題」，以及「寫作日誌淨字數（Net Word Count）演算法校準」，全面提升日常設定管理與寫作紀錄的穩定性。

## 更新重點

### 1. 資料集卡片即時自動儲存（Auto-save）
- 移除右側資料集面板底部的「儲存卡片變更」按鈕，改為輸入文字時即時同步儲存。
- 作家在編輯卡片標題或正文時，系統自動於背景寫入資料模型，切換不同卡片或章節時不再有未儲存而遺失內容的風險。
- 加入訊號阻斷防護（Signal Blocking），在切換卡片載入資料時避免觸發多餘的儲存流程，確保介面切換流暢。

### 2. 修復卡片工具列前綴切換崩潰問題
- 補齊基底文字編輯元件（BaseRichTextEdit）的 `toggle_line_prefix` 邏輯。
- 修復先前在右側卡片編輯器點擊工具列「標題（H）」或「清單項目（•）」按鈕時引發的程式崩潰問題。
- 支援單行與多行選取，若選取區塊已具備前綴則自動移除，若無前綴則批次新增，提升 Markdown 格式化編輯體驗。

### 3. 寫作日誌字數邏輯校準（淨字數 Net Word Count）
- 調整後台日誌寫入演算法，從原本的「毛字數（Gross，僅累加不扣除）」調整為「淨字數（Net）」。
- 當日存入資料庫的進度會強制對齊編輯器主介面顯示的「今日進度」，徹底解決在發生異常恢復或重啟軟體後，寫作日誌記錄之「今日字數」大於專案實際淨增加字數的數據不一致問題。

### 4. 測試套件維護與 100% 綠燈驗證
- 同步更新右側面板分割與自動儲存相關的介面測試案例。
- 全套 40 個測試模組、257 項自動化單元與整合測試持續維持 100% 綠燈通過。
